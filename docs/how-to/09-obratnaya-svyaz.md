# Включить обратную связь

Обратная связь - публичная доска на том же сайте: `http://<адрес>/index.php?feedback`. Любой заводит нумерованное обращение, любой отвечает, всё видно всем. Ни входа, ни профилей, ни загрузки файлов, ни модерации по умолчанию - только автоматика: лимиты частоты, приманка для ботов и минимальная задержка отправки.

Вход на страницу один - кнопка в подвале главной, со значком числа обращений без ответа.

## Шаг 1. Проверь, что она включена

```php
'feedback' => true,
```

Это значение по умолчанию. `false` - страница отдаёт 404, обработчики отправки закрыты, ссылки в подвале не рисуются.

## Шаг 2. Дай данным пережить пересоздание контейнера

Диалоги лежат в `feedbackPath` - по умолчанию `/var/www/YT_data/feedback`. Это **выше** корня сайта (`/var/www/YT`) намеренно: отдать каталог по HTTP нельзя в принципе, а не только правилом `deny` в nginx. Возрастная чистка сюда не ходит, отзывы вечны.

Каталог живёт внутри контейнера, поэтому без volume он исчезнет вместе с ним:

```yaml
    volumes:
      - yt_feedback:/var/www/YT_data
```

Один диалог - один JSON-файл (`d/000123.json`). Никакой базы данных, забрать доску целиком можно `docker cp`.

## Шаг 3. Настрой права администратора

Администратор умеет то, чего не может обычный посетитель: удалять сообщения и обращения, отвечать от своего имени. Дверей две, и работают они независимо.

**Дверь первая - доверенная сеть.** Адреса из `feedbackAdminNetworks` (список CIDR, IPv4 и IPv6) получают кнопки без пароля:

```
FEEDBACK_ADMIN_NETWORKS=127.0.0.1/32,::1/128,192.168.1.0/24
```

**Дверь вторая - пароль.** Задаётся переменной окружения, чтобы не лежать в git:

```
FEEDBACK_ADMIN_PASSWORD=
```

Принимается и обычная строка, и готовый хеш - хеш надёжнее, при утечке файла настроек пароль из него не достать:

```bash
php -r 'echo password_hash("свой-пароль", PASSWORD_DEFAULT), "\n";'
```

Пароль спрашивается на **каждое** действие, метки в сессии нет намеренно: иначе угнанная кука давала бы права до конца сессии. Неудачные попытки считаются по скользящему окну - 5 за 10 минут (`feedbackAdminTries`, `feedbackAdminTriesWindow`), верный пароль счётчик не двигает.

Текст отказа одинаков для "пароль неверный" и "пароль не настроен" - какая из дверей вообще существует, снаружи знать незачем.

Если обе двери пусты, действий администратора нет ни у кого. Это рабочая конфигурация: доска живёт на одной автоматике.

С администратора сняты все ограничения, кроме физических: лимиты частоты, минимальная задержка, приманка, потолки длины и количества на него не действуют. Проверка свободного места остаётся - это не право, а физика.

## Шаг 4. Грабля с обратным прокси (обязательно прочитать)

Если Качалка стоит за пограничным nginx - а в продакшене она стоит - запрос всегда приходит с приватного адреса. Поэтому реальный адрес посетителя берётся из заголовков `X-Real-IP` / `X-Forwarded-For`, и требование к прокси одно:

```nginx
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $remote_addr;   # ЗАМЕЩАТЬ, а не дополнять
```

Стандартный Debian-овский `proxy_params` собирает `X-Forwarded-For` через `$proxy_add_x_forwarded_for`, то есть **дописывает** к тому, что прислал клиент. Пока адрес использовался только для лимитов частоты, ценой ошибки был обход лимита. С появлением доверенных сетей администратора цена другая: запрос с подставленным заголовком выдаёт себя за адрес из списка и получает кнопки удаления.

Проверить свой конфиг:

```bash
grep -rn "X-Real-IP\|X-Forwarded-For" /etc/nginx/
```

Полный разбор пограничного конфига - в [Поставить сайт за HTTPS](06-reverse-proxy-https.md).

Остаётся один путь подделки - прямое обращение к порту контейнера мимо nginx, с приватного адреса. Кто это может, тот и так уже внутри домашней сети.

## Что стоит на входе против спама

Значения по умолчанию, все меняются в `config.php`:

| Что | Ключ | Значение |
|---|---|---|
| Пауза между двумя сообщениями | `feedbackMsgWindow` | 10 секунд |
| Сообщений в час | `feedbackMsgHour` | 10 |
| Новых обращений в сутки | `feedbackDialogDay` | 3 |
| Задержка от открытия формы до отправки | `feedbackMinDelay` | 3 секунды |
| Потолок числа обращений | `feedbackMaxDialogs` | 5000 |
| Потолок сообщений в одном обращении | `feedbackMaxPerDialog` | 200 |

Плюс приманка: скрытое поле формы, которое человек не видит и не заполняет, а заполнялка бота - заполняет. Оно уводится за край экрана, а не прячется `display: none` - часть ботов такие поля пропускает.

Отправитель опознаётся по HMAC от его адреса с локальным секретом. Ни IP, ни User-Agent, ни куки в файл диалога не попадают вовсе.

Потолки нужны отдельно от лимитов частоты: лимиты держат одного отправителя, но не всех сразу. При достижении потолка обращений новые не заводятся, а ответы в существующие продолжают работать.

## Что умеет разметка сообщений

Сообщения рендерятся безопасным подмножеством Markdown: заголовки, списки, цитаты, таблицы, горизонтальная черта, `код` и блоки кода с подсветкой, жирный и курсив, ссылки. Картинок нет намеренно.

Ссылка пропускается только со схемой `http` или `https`, всё остальное рисуется обычным текстом. Сырой HTML невозможен по построению, а не по списку запретов: текст экранируется целиком **до** разбора, поэтому тегу неоткуда взяться. Подробнее - в [Безопасности](../explanation/05-bezopasnost.md).

## Смотреть события

Каждое действие пишется строкой в `/var/log/feedback.log`, а `tail` из точки входа контейнера выводит его в общий поток:

```bash
docker logs -f yt | grep feedback
```

Формат: `дата | feedback | событие | #id | ip=... | поле=значение`. События - новое обращение, ответ, удаление сообщения, удаление обращения.

IP в лог пишется намеренно: это служебный лог владельца, по нему видно источник спама. Дальше этого файла адрес не уходит. Текста сообщения в строке нет - только длина: тело может содержать то, что человек не должен был присылать, и лог не место это размножать.

Выключить лог - пустое значение `feedbackLogFile`.

## Не работает?

- **Страница отдаёт 404** - `'feedback' => false` в конфиге. Других причин у 404 на этом адресе нет.
- **Обращения исчезли после `docker compose up`** - не подключён volume на `/var/www/YT_data`, каталог жил внутри контейнера. Восстановить нечего, дальше - подключить volume.
- **Кнопки администратора не появляются из дома** - адрес не попал в `feedbackAdminNetworks`, либо прокси не перезаписывает `X-Forwarded-For` (шаг 4). Что видит сервер, покажет строка `ip=` в логе событий.
- **"Слишком быстро" при честной отправке** - сработала минимальная задержка `feedbackMinDelay`, отсчёт идёт от открытия страницы. Форма, открытая и отправленная за секунду, выглядит как бот.
- **Отправка молча не проходит** - проверь свободное место: при остатке меньше 100 МБ запись отклоняется намеренно.
