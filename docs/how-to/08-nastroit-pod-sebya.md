# Настроить сайт под себя

Все настройки сайта лежат в одном файле - `app/var/www/YT/config/config.php`. Полный список параметров с описанием - в [Параметрах конфигурации](../reference/01-config-parametry.md). Здесь - готовые рецепты для частых задач.

Файл запекается в образ, поэтому правка применяется после пересборки:

```bash
docker build -t yt . && docker compose up -d
```

Если правишь настройки часто, примонтируй файл с хоста и обходись рестартом контейнера:

```yaml
    volumes:
      - ./config.php:/var/www/YT/config/config.php:ro
```

Секреты (прокси, пароль администратора) в этот файл вписывать не нужно - они читаются из переменных окружения, см. [Параметры конфигурации](../reference/01-config-parametry.md#переменные-окружения).

## Поменять название сайта

```php
'siteName' => 'Моя качалка',
```

## Ограничить качество видео по умолчанию

```php
'maxVideoRes' => 1080,
```

Это ограничивает только обычную кнопку "Скачать". Долгое удержание кнопки всё равно позволит выбрать явное качество (4K, 2K, 1080p), даже выше этого потолка - так задумано.

## Разрешить или запретить несколько загрузок одновременно

```php
'max_dl' => 1,
```

`1` - одна загрузка за раз, остальные ждут очереди. `-1` снимает лимит совсем - не рекомендуется, особенно если качаешь с YouTube (см. [что влияет на скорость бана IP](../explanation/06-youtube-i-perevod-kak-eto-rabotaet.md#что-влияет-на-скорость-бана-ip)).

## Отключить конвертацию в аудио

Если ffmpeg недоступен или не хочется тратить на конвертацию ресурсы сервера:

```php
'disableExtraction' => true,
```

## Поменять папку для скачанных файлов

```php
'outputFolder' => '/var/www/YT/download',
'downloadPath' => 'download',
```

`outputFolder` - абсолютный путь на диске, `downloadPath` - относительный веб-путь, по которому файл можно скачать прямо по ссылке из браузера. Если оставить `downloadPath` пустым, ссылки на скачивание вообще не показываются - подходит, если файлы забираются каким-то другим способом (например, по сети).

## Поменять время жизни файлов

```php
'retentionMinutes' => 120,
```

Само удаление делает хостовый cron (см. [Установка через Docker](01-ustanovka-docker.md#настрой-автоочистку-и-автообновление)), но правится только эта цифра: `2hourcleanup.sh` читает `retentionMinutes` из того же `config.php` (через php-cli, при неудаче - `sed`, а если не вышло и это - 120 по умолчанию) и подставляет её в свой `find -mmin +N`. Таймер на сайте и реальное удаление двигаются вместе, второго места правки нет.

## Ускорить закачку

```php
'externalDownloader' => true,
'concurrentFragments' => 4,
```

Два независимых механизма. `externalDownloader` отдаёт цельный файл внешнему загрузчику aria2c, который тянет его несколькими диапазонами сразу - но только с прямых доменов: SOCKS5 aria2 не понимает вообще, а живые эфиры и ссылки с меткой времени качает ffmpeg. `concurrentFragments` - про фрагментированное видео (VK, Rutube, любой DASH/HLS), где никакого "одного большого файла" нет и aria2c бесполезен; потолок 4, на YouTube не применяется никогда.

Число соединений не константа: оно считается на старте каждой задачи из обстановки и схлопывается до одного, если рядом уже работает другая задача или хост недавно ответил 429. Подробности - в [Очереди и других технических решениях](../explanation/04-ochered-i-fishki.md#ускорение-закачки).

Для aria2c нужен пакет `aria2` в образе. В готовом образе он есть.

## Выключить проверку кодеков готового видео

```php
'mp4Compat' => false,
```

Качалка отдаёт видео в mp4 всегда, но правильного контейнера мало: VP9 и Opus кладутся в mp4 законно, а Safari, iOS и QuickTime такой файл не откроют - расширение есть, воспроизведения нет. Поэтому после загрузки задача зовёт `ensure_mp4.sh`: тот смотрит `ffprobe`, что внутри, и перекодирует **только несовместимую дорожку** (видео в H.264, звук в AAC). Заодно чинит контейнер, если ремукс не удался и файл остался в исходном формате.

Обычному видео (H.264 + AAC) это стоит одного вызова `ffprobe` и ничего не меняет. HEVC и AV1 считаются приемлемыми: перекодировать их - потерять качество и занять процессор ради узкого круга старых плееров.

Выключать имеет смысл на слабом сервере, если не жалко получать иногда файлы, которые откроются не везде. Ролики длиннее 90 минут не перекодируются в любом случае - это защита от того, чтобы восьмичасовая запись эфира не заняла сервер на сутки.

## Настроить паузу после отказа сайта

```php
'hostCooldownMinutes' => 10,
```

Сколько минут не трогать хост после его 429 ("слишком много запросов"). `0` отключает паузу совсем - не рекомендуется, это прямой путь к более длинной блокировке.

## Записывать эфиры целиком

```php
'liveFromStart' => true,
'waitForVideo' => true,
```

Первый ключ пишет трансляцию с начала эфира, а не с момента подключения (только YouTube). Цена честная: задача сначала докачивает пропущенный хвост, поэтому идёт дольше, быстрее ест диск, а готовый файл появляется в списке только в конце. Метка времени в ссылке (`&t=`) ключ отключает - вместе они бессмысленны.

Второй разрешает поставить ссылку на анонсированный стрим заранее: задача дождётся начала и запишет сама. Ждущая задача **не занимает** слот очереди, иначе при `max_dl = 1` она заперла бы всё на часы, ничего не качая. Задачу, залипшую на ожидании эфира, которого не будет (возрастной гейт, бот-чек), гасит сторож - иначе она ждала бы вечно и не дошла бы до повтора с куками.

## Включить или выключить обратную связь

```php
'feedback' => true,
```

`false` - страница `?feedback` отдаёт 404, все четыре обработчика отправки закрыты, ссылки в подвале не рисуются. Настройка доски целиком - в [Включить обратную связь](09-obratnaya-svyaz.md).

## Запретить пользователям удалять файлы

```php
'allowFileDelete' => false,
```

## Включить debug-режим (только для разработки)

```php
'debug' => true,
```

Показывает все ошибки PHP прямо на странице. Ни в коем случае не включай на сервере, доступном из интернета - это раскрывает внутренние пути и детали реализации.
