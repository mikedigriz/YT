# Коды ошибок yt-dlp

yt-dlp сам по себе выдаёт технические сообщения об ошибках на английском. Качалка разбирает лог по таблице правил и подменяет его на короткое понятное сообщение на русском. Правила проверяются по порядку сверху вниз, первое совпадение побеждает - поэтому сетевые ошибки идут раньше, чем ошибки контента.

Таблица ниже - это `ERROR_RULES` из `app/var/www/YT/class/Downloader.php`.

## Бот-детект YouTube

| Что видит yt-dlp | Что видит пользователь |
|---|---|
| `cookies are no longer valid` / `cookies have expired` | Куки протухли. Надо зайти под тем же аккаунтом и обновить cookies.txt на сервере |
| `not a bot` / `Sign in to confirm you're not a bot` | YouTube принял нас за бота. IP прокси засвечен - лучше подождать |

Название сайта в сообщении про куки подставляется по ссылке задачи: YouTube, Instagram или TikTok. Правило вынесено из общей таблицы именно поэтому - текст у него не фиксирован.

## Сетевые ошибки

| Что видит yt-dlp | Что видит пользователь |
|---|---|
| `Name or service not known` / `Could not resolve host` | DNS не резолвил хост. Проверь ссылку или интернет |
| `Connection refused` / `ECONNREFUSED` | Сервер сказал "нет". Connection refused |
| `timed out` / `ETIMEDOUT` | Тайм-аут. Сервер слишком долго молчит |
| `Network is unreachable` / `ENETUNREACH` | Сеть недоступна |
| `No route to host` | Маршрута до хоста нет. Проверь прокси/сеть |
| `HTTP Error 429` / `Too Many Requests` | Сайт оверлоуд. Подожди |
| `HTTP Error 403` / `403 Forbidden` | 403 Forbidden. Не пущает - нужен прокси/куки |
| `HTTP Error 404` / `404 Not Found` | 404 Not Found. Страницы больше нет |
| `HTTP Error 503` | 503. Сайт прилёг |
| `HTTP Error 500` | 500. У сайта внутренние проблемы |
| `SSL handshake` / `certificate verify failed` | Ошибка SSL/HTTPS. Сертификат не прошёл проверку |
| `Unable to download webpage` | Не удалось открыть страницу |
| `Unable to connect to` / `Connection aborted` | Соединение оборвалось. Попробуй ещё раз |

## Что происходит после ошибки

Не каждая ошибка окончательна - часть Качалка разбирает сама. Повтор в любом случае один на задачу и стартует через 10 секунд после падения: за это время человек успевает прочитать статус ("Пробую через прокси", "Пробую с куками аккаунта", "Пробую другим клиентом YouTube"), и только потом его перебивает прогресс новой попытки.

| Ошибка | Что делает Качалка |
|---|---|
| Сетевая (тайм-аут, DNS, 429, 503) | Один раз перезапускает задачу через прокси. Повтор один на задачу, отметка о нём пишется в лог. |
| Закрытый контент, бот-чек, "нужна авторизация" | Один раз повторяет с куками того сайта, если они настроены и в первой попытке не использовались. |
| `unable to download video data` + `HTTP Error 403` на ссылке YouTube | Один раз повторяет другим клиентом YouTube (`android_vr`, без PO-токена). Повтор той же командой тут бесполезен: CDN отбил ссылку, привязанную к токену конкретного клиента. |
| Задача залипла на ожидании эфира, которого не будет (возрастной гейт, бот-чек) | Сторож гасит её и финализирует лог **без** пометки "Отменено" - чтобы сработал повтор с куками. |
| `HTTP Error 429` при завершении задачи | Дополнительно ставит хосту паузу на `hostCooldownMinutes`. Задачи этого сайта остаются в очереди, слот забирает другой хост. |
| Любая из перечисленных, но файл на диске уже есть | Не делает ничего. yt-dlp мог сам пережить 503 внутри своей задачи и всё-таки дописать файл - без этой проверки удачная загрузка качалась бы второй раз. |

Ошибка постобработки (`ERROR: Conversion failed!`) отдельно подхватывается скриптом `ensure_mp4.sh`: когда ремукс в mp4 не удался, yt-dlp оставляет исходный файл лежать рядом с огрызком от упавшего ffmpeg, и оба показываются в списке как готовые. Скрипт пробует переупаковать файл сам и записывает результат поверх огрызка. Если дорожка не читается вообще, он честно не трогает ничего - задачу пометит неудачной проверка ниже.

Отдельно от таблицы правил живёт проверка готового файла: yt-dlp умеет выйти с кодом 0 и оставить огрызок (сеть умерла на последних байтах, постпроцессор упал, диск кончился). Готовый файл прогоняется через `ffprobe`, и если он не читается, в лог дописывается строка `ERROR:` - задача честно становится неудачной вместо "Готово" поверх битого файла. Отменённые вручную задачи не проверяются: там файл обрезан намеренно.

Ожидание анонсированного эфира ошибкой не считается вовсе: вместо "трансляция ещё не началась" в статусе пишется "Жду начала эфира, слот очереди не занимаю".

## Если ничего не подошло

Если ни одно правило не сработало, пользователю показывается сырая строка `ERROR:` прямо из лога yt-dlp (уже прогнанная через санитизацию) - без перевода, но хоть что-то. А если в логе нет даже `ERROR:` - честное "ХЗ, что случилось. Смотри лог".

Как добавить новое правило: вставить строку в таблицу `ERROR_RULES` в `class/Downloader.php` - порядок значим, более специфичные и приоритетные ошибки должны стоять выше общих.
