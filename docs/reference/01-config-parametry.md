# Параметры конфигурации

Все настройки сайта лежат в одном файле - `app/var/www/YT/config/config.php`. Файл возвращает обычный PHP-массив с комментариями к каждому параметру.

| Параметр | По умолчанию | Что значит |
|---|---|---|
| `siteName` | `'Качалка v.1.0b'` | Название, которое видно в заголовке страницы и в `<title>`. |
| `siteTheme` | `'lumen'` | Тема Bootswatch (`css/{тема}.min.css`). Можно переопределить на лету через `?theme=` в адресе. |
| `winterMascot` | `'auto'` | Зимний вид маскота. `'auto'` - по календарю (ноябрь - март), `'on'`/`'off'` - принудительно. |
| `disableExtraction` | `false` | Если `true` - убирает возможность конвертации в аудио. |
| `max_dl` | `1` | Сколько загрузок может идти одновременно. `-1` убирает лимит совсем. |
| `outputFolder` | `/var/www/YT/download` | Абсолютный путь, куда сохраняются скачанные файлы. |
| `downloadPath` | `'download'` | Относительный веб-путь к папке загрузок. Пустое значение - ссылки на скачивание не показываются. |
| `redirectAfterSubmit` | `'downloads'` | На какую вкладку перекинуть пользователя после отправки ссылки на загрузку. |
| `logPath` | `/var/www/YT/tmp` | Папка, куда yt-dlp и сам сайт пишут служебные файлы: прогресс, очередь, PID-файлы. |
| `logURL` | `''` | Если эта папка доступна через веб - относительный путь до неё, чтобы в интерфейсе появилась ссылка на лог загрузки. Пустое значение - логи не публикуются. |
| `youtubedlExe` | `/.yt_env/bin/yt-dlp` | Путь к исполняемому файлу yt-dlp. |
| `maxVideoRes` | `1080` | Потолок качества видео при обычном нажатии кнопки "Скачать". Долгое нажатие позволяет выбрать качество явно, поверх этого потолка. |
| `socks5` | из `.env` | Адрес SOCKS5-прокси. Читается через `getenv('SOCKS5_URL')`. |
| `proxyStatus` | `true` | Показывать ли индикатор живости прокси в футере. Работает только если `socks5` не пустой. |
| `keepPartialFiles` | `false` | Оставлять ли недокачанные `.part`-файлы после нажатия "Остановить всё". На оборванные записи трансляций не влияет - они переименовываются в обычный файл раньше этой уборки. |
| `disableQueue` | `false` | Если `true` - при превышении лимита `max_dl` загрузка не запустится, вместо того чтобы встать в очередь. |
| `allowFileDelete` | `true` | Разрешить ли пользователям удалять файлы из интерфейса. |
| `showFileLifetime` | `true` | Показывать ли таймер "сколько осталось до автоудаления" у каждого файла. Имеет смысл только если настроен хостовый cron очистки. |
| `retentionMinutes` | `120` | Окно жизни файла в минутах - шкала для таймера в интерфейсе. Его же читает хостовый cron очистки (`2hourcleanup.sh`) для своего `find -mmin`, поэтому шкала и реальное удаление двигаются вместе. |
| `liveFromStart` | `true` | Писать трансляцию с начала эфира, а не с момента подключения (`--live-from-start`, только YouTube). Метка времени в ссылке (`&t=`) ключ отключает. |
| `waitForVideo` | `true` | Ждать начала анонсированного эфира вместо ошибки "трансляция ещё не началась" (`--wait-for-video`, только YouTube). Ждущая задача не занимает слот `max_dl`. |
| `hostCooldownMinutes` | `10` | Сколько минут не трогать хост после его 429. Задачи такого хоста остаются в очереди, слот забирает следующая задача другого сайта. |
| `externalDownloader` | `true` | Отдавать закачку внешнему загрузчику aria2c. Работает только на прямых доменах: SOCKS5 aria2 не поддерживает. Живые эфиры, ссылки с меткой времени и YouTube исключены. Требует пакета `aria2` в образе. |
| `mp4Compat` | `true` | Проверять кодеки готового видео и приводить к воспроизводимому mp4 (`ensure_mp4.sh`). Контейнер даёт `--remux-video`, но контейнера мало: VP9 и Opus кладутся в mp4 законно, а Safari, iOS и QuickTime такой файл не откроют. Перекодируется только несовместимая дорожка, здоровый h264+aac не трогается вовсе. |
| `concurrentFragments` | `4` | Сколько фрагментов качать параллельно (`--concurrent-fragments`), `0`/`1` - выкл, `4` - потолок. Главный ключ для фрагментированного видео (VK, Rutube, DASH/HLS). На YouTube не применяется никогда. |
| `debug` | `false` | Включает вывод всех PHP-ошибок на экран. Не включать на сервере, доступном из интернета. |
| `youtubeCookiesFile` | `/var/www/YT/config/youtube_cookies.txt` | Путь к файлу кук YouTube (Netscape `cookies.txt`). Файла нет - куки просто не используются. Подключается только повторной попыткой при блокировке, не к каждой загрузке. |
| `instagramCookiesFile` | `/var/www/YT/config/instagram_cookies.txt` | Путь к файлу кук Instagram. Подключается сразу, с первой попытки - без входа Instagram почти ничего не отдаёт. Файла нет - качается без кук. |
| `tiktokCookiesFile` | `/var/www/YT/config/tiktok_cookies.txt` | Путь к файлу кук TikTok. Подключается сразу, как у Instagram: без авторизации TikTok часто отвечает "Your IP address is blocked from accessing this post". |

Как настроить куки - в [Починить обход бот-чека](../how-to/05-obhod-bot-cheka.md#подключить-куки-аккаунта-запасной-путь). Как настроить прокси - в [Настроить SOCKS5-прокси](../how-to/03-socks5-proxy.md). Почему одни домены (`DIRECT_ACCESS_DOMAINS`) всегда идут напрямую, а не через прокси - в [Backend](../explanation/02-backend.md#список-доменов-прямого-доступа).

## Обратная связь

Публичная доска на `index.php?feedback`. Как её настроить целиком - в [Включить обратную связь](../how-to/09-obratnaya-svyaz.md).

| Параметр | По умолчанию | Что значит |
|---|---|---|
| `feedback` | `true` | Включена ли доска. `false` - страница отдаёт 404, обработчики отправки закрыты, ссылки в подвале не рисуются. |
| `feedbackPath` | `/var/www/YT_data/feedback` | Каталог с диалогами. Лежит выше корня сайта намеренно - отдать его по HTTP нельзя в принципе. Возрастная чистка сюда не ходит. Перебивается `FEEDBACK_PATH`. |
| `feedbackPerPage` | `20` | Сколько обращений на странице списка. |
| `feedbackLogFile` | `/var/log/feedback.log` | Файл событий (новое обращение, ответ, удаление). Его читает `tail` из точки входа контейнера, поэтому строки видны в `docker logs`. Пустое значение выключает лог. Перебивается `FEEDBACK_LOG_FILE`. |
| `feedbackMsgWindow` | `10` | Секунд между двумя сообщениями одного отправителя. |
| `feedbackMsgHour` | `10` | Сообщений в час с одного отправителя. |
| `feedbackDialogDay` | `3` | Новых обращений в сутки с одного отправителя. |
| `feedbackMinDelay` | `3` | Секунд от открытия формы до отправки. Быстрее - похоже на бота. |
| `feedbackMaxDialogs` | `5000` | Потолок числа обращений. При достижении новые не заводятся, ответы в существующие продолжают работать. |
| `feedbackMaxPerDialog` | `200` | Потолок сообщений в одном обращении. |
| `feedbackAdminPassword` | из `.env` | Пароль администратора. Принимается и готовый `password_hash()`, и обычная строка. Пусто - права только у доверенных сетей. Читается через `getenv('FEEDBACK_ADMIN_PASSWORD')`. |
| `feedbackAdminNetworks` | `127.0.0.1/32`, `::1/128`, `192.168.1.0/24` | Сети (CIDR, IPv4 и IPv6), из которых кнопки администратора работают без пароля. Перебивается `FEEDBACK_ADMIN_NETWORKS` целиком. |
| `feedbackAdminTries` | `5` | Неудачных попыток пароля на источник за окно. Верный пароль счётчик не двигает. |
| `feedbackAdminTriesWindow` | `600` | Длина этого окна в секундах. |

Лимиты частоты считаются по источнику, а источник опознаётся по HMAC от его адреса с локальным секретом - сам адрес нигде не хранится.

## Переменные окружения

Значения, которым не место в git, приходят из окружения - через `.env` рядом с `docker-compose.yml` (`env_file`). Образец - [`.env.example`](../../.env.example). Переменная всегда перебивает то, что написано в `config.php`.

| Переменная | Что задаёт |
|---|---|
| `SOCKS5_URL` | Адрес SOCKS5-прокси, формат `socks5://user:pass@host:port`. Пусто - проксирования нет. |
| `FEEDBACK_ADMIN_PASSWORD` | Пароль администратора доски. Лучше класть хеш: `php -r 'echo password_hash("пароль", PASSWORD_DEFAULT), "\n";'`. |
| `FEEDBACK_ADMIN_NETWORKS` | Список CIDR через запятую. Пустая строка означает "доверенных сетей нет" - это не то же самое, что отсутствие переменной (тогда действует список из `config.php`). |
| `FEEDBACK_PATH` | Каталог диалогов. Нужен, чтобы гонять страницу вне контейнера, где `/var/www` не существует. |
| `FEEDBACK_LOG_FILE` | Файл лога событий. Нужен там же, где `/var/log` недоступен. |

Внешний адрес в списке доверенных сетей держи именно в `.env`: `config.php` лежит в git, `.env` - нет.

## Фильтр 18+ в yt-dlp.conf

Файл `app/etc/yt-dlp.conf` - общий конфиг, который yt-dlp подхватывает при каждом запуске. В нём есть `--match-filter` - регулярное выражение со списком доменов для взрослых. Если ссылка ведёт на сайт из этого списка, yt-dlp откажется её скачивать ещё до старта загрузки.

## nginx

Конфиг лежит в `app/etc/nginx/sites-available/default`:

- Запросы к `.php`-файлам уходят в php-fpm через unix-сокет.
- Папки `tmp`, `class` и `config` полностью закрыты от прямого доступа через веб (`.yt_env` физически лежит вне веб-корня `/var/www/YT`, поэтому веб и так до него не дотягивается).
- Файлы `.php` в папках `download/` и `favicons/` не исполняются, отдаются только как статика.
- Картинки, шрифты и звуки уведомлений кешируются на неделю, иконки сайтов - на год.
- CSS и JS отдаются с версией в query-строке (`?v=<хэш содержимого сборки>`, см. [Кэш-бастинг статики](../explanation/04-ochered-i-fishki.md#кэш-бастинг-статики-и-баннер-сайт-обновили)), поэтому кешируются на год как `immutable` - устаревание невозможно в принципе, новая сборка сама даёт новый URL.
- Ответ `index.php` явно помечен `no-cache, no-store, must-revalidate` - CSRF-токен в разметке должен доходить до браузера свежим после каждой пересборки, без ручного сброса кеша (`Ctrl+Shift+R`).
- Таймаут ответа от PHP ограничен 30 секундами.

Для проверки живости контейнера есть лёгкий эндпоинт `health.php` - отдаёт только `200 OK`, не запуская фронт-контроллер. Именно его дёргает Docker `HEALTHCHECK`.
